## Section 0 — Do these five things this week

Each item: the action, why it is first, effort, and the acceptance test. All ≤1 founder-day.

**1. Make `pw status` stop contradicting itself (F1, G1 → R1).** On every joined machine,
the first command a user runs prints `✓ Joined <url> …` and then `· Not joined — pw join …`
— deterministically, every time (`agent.py:375-377` writes a `"default"` string key into
`join.json`; `doctor.py:77-79` crashes on it; the `except` at `doctor.py:82-83` prints the
contradiction). A second coordinator is silently never shown. In a project whose brand is
honesty, the health command lies. *Effort:* ~1 h including the missing test (render a
populated `join.json` through `doctor.main` — that branch has zero coverage today).
*Accept:* `pw status` on a joined machine prints exactly one truthful membership line per
coordinator; a regression test exists.

**2. Refuse to ship a "live web" report with zero sources (G13 → R2).** When DDG
rate-limits and every analyst returns its honest "(No … sources reachable for this brief)" note
(wording varies by scope, researcher.py:345-347), `local.run()` still
compiles and writes a full report with a "live web" byline (`local.py:246-263`,
`judge.py:304-306`) — the executive summary is model memory wearing a lab coat. The honest-
product promise breaks exactly when it matters most. *Effort:* ~half a day. *Accept:* a run
with 0 web+library sources exits with an honest failure (and fix hints), never a confident
report; `--json` and the MCP tool expose a machine-readable `sources` count.

**3. Decide the consent question as an ADR, not a silence (F2 → R4).** README:130-131 ("you always see and consent to what your machine does") and :282-283
("operators always see and consent to the work their machine does") make the promise; the `pw join` daemon
auto-executes answer/judge/batch/research tasks with no per-task prompt (`agent.py:234→251`)
— per-task consent exists only in the `assisted` flow. Two honest resolutions; pick one in
DECISIONS.md (candidate D53): (a) consent modes — `pw work --ask` prompts per task, `--auto`
is an explicit opt-in; or (b) reword the promise to what the code does ("you choose the
kinds of work your machine accepts; every task is visible in the log"). *Effort:* the
decision is an evening; (b) is an hour, (a) is a round. *Accept:* the README's promise and
the daemon's behavior describe the same product.

**4. Make the repo agree on what the product is (F3, F4 → R5).** `docs/CONTEXT.md:48` calls
the network "the primary product and north star"; `README.md:13` says single-player
research "is the product"; the PyPI one-liner (`pyproject.toml:8`) leads network-first. A
newcomer following the README's own docs table lands on its own refutation. *Effort:* ~half
a day (Section 5.2 has the structural fix: VISION.md as single source of truth, CONTEXT.md
→ pointer, pyproject description rewritten, a consistency check in RELEASING.md). *Accept:*
grep for "primary product" returns one answer across README/CONTEXT/pyproject/ANNOUNCE.

**5. Ten minutes of first-impression hygiene (F9, F22, F23, F33 → R7-R9).** Delete
`arabtest2.json` (a stray, not-even-valid-JSON Arabic test string in every visitor's first
screenful); move `docs/BROWSER_SETUP.md` (an internal AI-assistant note) to
`docs/archive/`; add `[all]` to ANNOUNCE.md's two install commands (lines 39 and 57); link the *already-live* GitHub
Pages evidence site (it exists on the gh-pages branch — currently linked from nowhere) in
the README and `pyproject [project.urls]`. *Accept:* a stranger's first screenful contains
no artifacts of the founder's workflow, and the evidence site is reachable from PyPI.

## Section 1 — The thesis: from dream to reality

**The code is ready for strangers; the doors are not open.**

Thirty-six documented rounds, 412 offline tests that run in ~4.3 seconds, Ed25519-signed
deliverables, TOFU key pinning, escrow with conservation checks, an adversarial-review
culture that published its own 0/10 loss — this is more engineering rigor than most funded
projects ship (observed throughout; Appendix A). And yet: of the ten personas who encounter
this project, the three the *network* needs most — the worker with an idle PC, the asker
with a question, the host who would run a cell — dead-end or crawl through founder-shaped
tooling (P6-P8). The project's own decision log agrees the main gate is no longer needed:
*"With D36's rate limits, the network is now safe to open beyond invite-only"*
(DECISIONS.md:1056-1057, in D37 — conditional on enrollment tokens being switched on).

The dream in the founder's brief — decentralized AI that humanity benefits from — does not
need more cryptography or another job type. It needs doors, signage, and a first-run
experience that never lies. Everything in this review serves that sentence.

The single-player engine, honestly assessed: the happy path genuinely works and its error
messages are better than most tools ship (P3, steps 1-3) — but the honesty promise has
cracks precisely at the edges: a zero-source run ships a confident report (G13), `--deep`
silently degrades on slow machines (G18), and the entire currency edge is English-only
regex (G15) — the founder's own Arabic briefs get the degraded product.

### P3 — The solo researcher (flagship path)
**Who:** Privacy-conscious professional (lawyer/journalist/student) with a 16GB laptop; wants cited, current research without a cloud.
**Entry point:** README quickstart: `pip install 'passiveworkers[all]'` → `ollama pull qwen3:14b` → `pw status` → `pw research "…"`.
**Verdict: COMPLETES WITH BRUISES**

**Today:**
1. Install + pull go as documented, and first-run failures are genuinely well-handled: Ollama down yields `Can't reach Ollama at … Is it running? Start it with 'ollama serve'…` instead of a traceback (local.py:66-68); zero models yields `No usable Ollama models found. Try: ollama pull qwen3:14b` (local.py:78) (observed).
2. `pw status` is a real 1-second preflight — `✓ Ollama reachable at … — N model(s)`, cast preview, web-backend and library lines, closing `Ready to research.` / `Fix the ✗ item(s) above` (doctor.py:22-94) (observed). Best onboarding step in the product (opinion).
3. `pw research "…"` auto-picks a cross-family cast and prints `🔬 Deep research (standard) — analysts: … · editor: …` plus discovered angles (local.py:202-208) (observed). `--editor api` with no key fails *before* the 15-minute spend, not after (local.py:192-197) (observed).
4. Analyst 1 starts: `[1/3] qwen3:14b researching the live web…` — then silence for minutes. — FRICTION: between that line and the `12 sources · 390 words · 41s` summary, one analyst does plan (480s cap) + ~9 searches + refine + rerank + page fetches + draft + repair with zero emits; ResearchWorker has no progress hook and MCP blocks the whole run (G16). On a rate-limited day DDG retries 3x/query and sleeps ~4.6s even after the final failure — no run-scoped breaker, so the run stalls while hammering the limiter (G17).
5. The wait itself is under-managed. — FRICTION: worst case ~15-18 sequential generates; README hero says 7.2 min but the CPU-only tier is a 1-2h ceiling, with no ETA pre-flight (G24). Worse: one Ollama timeout in plan/refine, any analyst, or the judge crashes the whole 10-20 min run with a traceback — analyst #3 dying discards #1-2's finished work; only the draft phase degrades gracefully (G14).
6. `--deep` on this laptop quietly isn't deep. — FRICTION: the 240s PW_RESEARCH_DEADLINE (counted from t0, including plan + first searches) silently strips all refine rounds on slow machines, and the payload reports *requested* depth, not achieved (G18).
7. Report lands in `reports/` with `[S#]` citations and `📄 Report ready in X min · N words · M sources → …` (local.py:276) (observed) — on the happy path this is the promised artifact and it is good. — FRICTION: if every web source was unreachable, the same confident report still ships — compile is unconditional, analysts' honest "(No … sources reachable…)" notes get buried, and the byline stamps "live web" while the exec summary comes from model memory (G13). `[S2, S1]` spans are kept/dropped by their FIRST marker only, deleting valid citations wholesale (G21); a top-ranked PDF becomes 200KB of mojibake preferred as the extract over its clean snippet (G22).
8. They follow the README's own tuning advice. — FRICTION: `PW_MODEL_CAP_GB=3` (the README's hardware tip) silently disables full-page evidence — what the code itself calls "the single biggest quality lever" — because one env var fuses two unrelated knobs (G19). The README's SearXNG upgrade (`docker compose up -d searxng`) silently yields ZERO web sources from the container path, and on Linux the desk container can't even reach host Ollama (G25/G27).
9. If they brief in a language other than English — Arabic is the founder's own dogfood language — the entire currency edge (year injection, recency ordering, breaking-topic deepening, arXiv/Wikipedia routing) silently switches off: freshness detection is English-only regex (G15).

**Target (deltas):**
- Gate compile on total web sources: zero sources → non-zero exit or a report whose first line is a warning, never a "live web" byline (→ R2)
- Extend the draft phase's retry/degrade to plan/refine/judge; salvage finished analysts when a later one crashes (→ R3)
- Heartbeat emits inside the analyst loop plus a pre-run ETA from model size × depth tier (→ R26)
- Split the model-size cap from page-evidence, and report *achieved* depth/tier in output and payload (→ R15, R16)
- Language-neutral freshness signals (numeric dates, not English month regex) so non-English briefs keep the currency edge (→ R30)

**Metric:** With networking cut after model detection, `pw research` must exit non-zero or emit a report whose first line is an explicit NO-WEB-SOURCES warning; and killing Ollama mid-analyst-2 must still yield a partial report containing analyst 1's sources.

## Appendix B — What this review might get wrong

- **Two candidate findings were refuted in verification and dropped**, in this repo's own
  publish-the-losses spirit: (1) the claim that assisted→assisted stage chaining is a no-op
  — store.py:822's comment is merely stale; D39 pipelines DO set `then_spec` on assisted
  parents (it held ID F17, hence that gap in the F-sequence); (2) the claimed `--analysts`
  help/default mismatch — the real, smaller issue is the MCP-vs-CLI default gap, kept as
  F24r. The G-sequence likewise skips G33: two sweeps independently reported the same
  Python-3.14-classifier finding and the duplicate was merged into G3.
- **Persona journeys are simulated** from code and docs, not observed users. Every "Today"
  step was code-walked, but no stranger was actually watched. The per-persona metrics are
  how to replace simulation with observation.
- **Effort letters (S/M/L) are one reviewer's guesses**; the founder's own velocity across
  36 rounds is better calibration.
- **The docker-compose findings (G25–G27) were verified by reading the network guards and
  path code, not by running the containers.** The failure mechanisms are deterministic in
  code, but a live `docker compose up` reproduction is the real acceptance test.
- **Line numbers are as of commit 9662e76 (v0.4.0)** and will drift.
- **Single-lens bias:** this review deliberately leaned product/adoption. A security-first
  or performance-first pass would rank differently — and the project's own adversarial
  review rounds cover those lenses better than this document can.
